# Personal Reading Inbox 设计

## 目标

建立一个独立于 `training-infra-roadmap/` 的轻量阅读链接归档，用于保存用户临时发现、尚未开始或只读了一部分的论文、文档、博客与代码仓库，避免关闭链接后遗失。归档可以容纳算法、系统、工程文档等不同主题，不承担研究雷达筛选、优先级判断或正式知识沉淀职责。

## 目录结构

```text
reading_inbox/
├── README.md
└── YYYY/
    └── YYYY-MM.md
```

- 月份按用户发送链接的时间归档，不按材料首次发布日期归档。
- `README.md` 说明用途、字段和维护规则。
- 每个月使用一个 Markdown 文件，避免单文件长期膨胀，也方便按时间回看。

## 单条记录

每条记录只保留以下信息：

```text
## 标题

- 类型：paper / documentation / blog / repository / other
- 链接：用户提供的原始链接
- 添加时间：YYYY-MM-DD
- 阅读状态：未开始 / 阅读中 / 已读完
- 一句话：材料主要讨论什么
```

默认规则：

- 用户未说明阅读进度时，状态为 `未开始`。
- 用户明确说“看到一半”等表述时，状态为 `阅读中`。
- 用户确认读完后，状态更新为 `已读完`。
- 一句话描述只概括主题，不展开技术分析、价值评级或阅读建议。

## 来源处理

- 优先保留用户提供的链接，确保可以沿原入口继续阅读。
- 对论文或正式文档，通过原始来源页核验标题和主要内容后再记录。
- 如果来源暂时无法访问，不猜测标题或内容；标题和一句话均填写 `待核验`，不增加额外字段。
- “同一链接”按用户提供的原始 URL 精确匹配，不做 URL 归一化或论文 ID 推断。
- 重复收到完全相同的 URL 时，只更新首次发送月份中的原记录，不在新月份重复添加；`添加时间` 保留首次发送日期，阅读状态和一句话可以更新。

## 与现有知识库的边界

- 不写入 `training-infra-roadmap/tracking/`，因为材料不一定属于 Training Infra。
- 不写入 `training-infra-roadmap/reading_queue/`，因为该目录承担经过筛选后的正式阅读计划。
- 不要求 `Decision`、`Reason`、影响等级、关联主题或知识生命周期状态。
- 如果用户以后明确要求深入阅读或纳入知识库，再单独进入现有 Human-AI Workflow。
