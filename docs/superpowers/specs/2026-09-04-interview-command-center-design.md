## 1. 背景

主文档已经按六个 Part 组织 74 道唯一问题，也包含 Core 10 和按 Part 折叠的全量问题索引。现有结构适合系统学习，但面试现场常从“某段经历”“某项技术”或“某个数字”随机切入；当前两行项目/技术链接不能支持 5–10 秒内定位，且跳进长答案后缺少稳定的回链。

## 2. 目标与非目标

### 目标

1. 在文档前部新增“面试现场速查控制台”，提供项目经历和技术主题双入口。
2. 让自我介绍、5D 并行等高频内容可以一次点击直达唯一答案。
3. 支持按简历关键数字反查对应项目，降低面试现场回忆成本。
4. 每道题提供本 Part 和总控制台回链；需要精确回到点击原位时使用浏览器历史。
5. 保持 GitHub、本地 Markdown 阅读器和普通浏览器的基础兼容性。

### 非目标

1. 不复制答案，不创建第二套问答正文。
2. 不修改任何问题、回答、项目数字或证据边界。
3. 不把 74 道题全部再次平铺到文档开头。
4. 不依赖 Mermaid `click`、JavaScript、CSS sticky navigation 或阅读器插件。
5. 不新增远端工作分支；云端仍只维护 `main`。

## 3. 信息架构

新增显式锚点：

```html
<a id="interview-console"></a>
```

锚点放在“五句法”和知识边界提示之后。文档前部顺序调整为：

1. `0. 先看结论`
2. `0.1 面试现场速查控制台`
3. `0.2 一张图看懂我的能力主线`
4. `1. 整体视野与问题导航`
5. 六个 Part 的唯一问答正文

控制台只负责快速路由；能力图负责建立全局认知；Part 表、Core 10 和全量索引负责完整性。三层职责不得混用。

能力图本体、图例和 20–30 秒口述版保留；能力图下现有的“核心机制导航”和“项目证据导航”两行删除，因为它们已被控制台的双入口完整替代。这样能力图只表达能力关系，不再承担第二套链接目录。

## 5. 返回行为

### 5.1 精确返回原位

静态 Markdown 无法识别同一答案是从项目表还是技术表进入，也无法生成动态 `history.back()`。因此精确返回依赖浏览器返回键：

- macOS：浏览器返回按钮或 `⌘ + [`；
- Windows/Linux：`Alt + ←`。

控制台顶部用一句话说明该行为。

### 5.2 稳定回链

每道唯一问题的内容末尾、下一道题锚点之前，增加且仅增加一行：

```markdown
↩ [返回本 Part 导航](#part-ii) · ↑ [返回面试速查控制台](#interview-console)
```

`part-ii` 按问题实际归属替换为 `part-i` 至 `part-v`。Part VI 不含新的唯一问题，不批量插入题尾回链。回链放题尾而不是题首，避免阅读完长答案后还要向上滚动。

## 6. Markdown 表现规则

1. 使用原生二列表格，不使用嵌套 HTML 卡片，以保证 GitHub 渲染稳定。
2. 链接显示文本控制在 2–12 个字，例如“5D 并行”“CP-local logits”“Gateway 调度”。
3. 使用 `P0`、`项目证据` 等少量文本标签，不依赖颜色表达优先级。
4. 控制台后保留分隔线，再进入能力图和完整 Part 导航。
5. 现有答案锚点保持不变，避免外部链接失效。
