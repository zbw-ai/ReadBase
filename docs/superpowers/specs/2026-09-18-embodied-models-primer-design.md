## 2. 主要脉络：一条任务线，两种循环

全篇用同一个教学场景串联：**“请把桌上的杯子递给我。”**

场景逐步增加变化：桌上有两个杯子，需要澄清；人中途更改要求；杯子滑落，需要判断失败并调整。例子用于解释机制，不代表任何具体模型已经可靠实现全部能力。

### 2.1 执行循环：机器人此刻如何完成任务

用户提出需求 → 获取观察 → 理解与必要的澄清 → 决定接下来做什么 → 生成动作目标 → 控制器执行 → 观察结果 → 继续或修正。

写作边界：这是功能分解，不是强制软件架构。一个模型可能承担多项功能，也可以由多个模块协作；不要求每套系统都有独立 planner、VLA 和世界模型。

### 2.2 学习循环：机器人能力如何得到改进

获得示范或交互数据 → 整理训练样本 → 训练／适配模型 → 评估 → 部署使用 → 收集反馈 → 再改进。

写作边界：执行时重新规划不等于模型参数在线更新；不是每次部署都在做 RL，也不是所有系统都需要在线学习。

### 2.3 章节推进顺序

**任务与基础词汇 → 概念地图 → MLLM 理解与交互 → VLA 与动作生成 → 世界模型预测 → 数据与学习 → 执行和评估 → Infra 对照。**

先回答“是什么、为什么需要”，再回答“怎么做”，最后回答“系统为什么难”。

## 3. 正文大纲

### 第一章｜机器人拿起一个杯子，到底需要什么？

**核心问题：具身智能与普通聊天模型的任务有什么不同？**

- 语言描述、物理动作和环境反馈之间的关系。
- 机器人本体、相机与传感器、模型、控制器分别做什么。
- 最小词汇：observation、state、action、policy、trajectory、episode、embodiment。
- 用杯子例子解释可观测信息不等于完整环境状态。
- 操作、移动与人机交互任务的区别；正文以操作任务为主，不能据此代表全部机器人任务。

**读完产出**：能用自己的话描述一次“观察—动作—反馈”过程，不需要先学完整机器人学。

### 第二章｜先分清概念：模型、算法、系统和框架不是一回事

**核心问题：这些缩写处在什么层次，哪些是包含、重叠或组合关系？**

- MLLM 与 VLM：术语使用存在交叉；视觉—语言只是多模态的一种组合。
- VLA：强调视觉、语言与动作之间的映射，不限定唯一网络结构或训练方法。
- Policy、planner、controller：按功能解释，不将其全部等同于“大模型”。
- World Model：环境变化的预测模型，与策略模型的目标不同。
- BC／模仿学习、RL：学习方式；Transformer、Diffusion、Flow Matching：不同层面的结构或生成方法，不能排成一个互斥分类表。
- LeRobot、openpi、Isaac Lab：软件生态及用途，作为可跳过的旁注，只做定位，不讲安装；本章不要求记住框架名称。
- VLT：没有具体出处时保留歧义，不擅自确定展开形式；后续提供出处再补充。
- 不再把用户所说的 MLLM 误写成 vLLM；正文不展开无关的推理框架辨析。

**读完产出**：能按“任务／功能、模型、学习方法、工具”给术语归位。

### 第三章｜MLLM：机器人如何理解环境、理解人并与人交互？

**核心问题：不直接输出机械臂动作，多模态模型为什么仍然有价值？**

- 多模态输入：图像、视频、文本，以及具体模型支持的语音等模态；不默认每个 MLLM 都支持全部模态。
- 从输入到输出的直觉：模态编码、特征连接或融合、语言／推理骨干；明确这只是常见组织方式之一。
- 环境理解：物体、空间关系、事件与任务状态。
- 多模态交互：指代消解、询问澄清、结合观察回答、处理用户纠正。
- 任务分解、工具调用、进度检查和失败解释：如何为动作模块提供信息。
- “看懂了／说对了”与“空间量准确／动作可执行”之间的差距。

**读完产出**：能说明“哪个杯子？”和“怎样移动夹爪？”是不同问题，以及 MLLM 在其中的作用。

### 第四章｜VLA 与动作策略：从理解任务到生成动作

**核心问题：语言指令最后如何变成机器人可执行的目标？**

- VLA 的输入输出，以及视觉、语言、机器人状态和动作模块的关系。
- Action 的具体含义：关节目标、末端位姿或位姿增量、夹爪状态等；单位、坐标系及控制接口需要明确。
- Action chunk：一次预测多步动作；区分预测长度、实际执行长度和重规划频率。
- 动作生成的几种直觉：直接回归、离散 action token、自回归生成、Diffusion／Flow Matching 连续动作生成。
- 用同一动作例子说明这些方案的区别，不把 Diffusion 与 Flow Matching 当作完全相同的方法。
- 简述 ACT、OpenVLA、π 系列的代表性思路；不把 ACT 当成必然具备语言输入的 VLA。
- 输出动作目标不等于直接控制电机电流；与低层控制、安全机制衔接。

**读完产出**：能解释一个动作向量和一段动作序列，而不仅是背出 VLA 的全称。

### 第五章｜World Model：预测“接下来会发生什么”

**核心问题：预测环境未来，和决定下一步动作有什么不同？**

- 世界模型的输入输出：状态／观察历史，以及在动作条件模型中加入候选动作；输出未来观察、潜在状态等，取决于具体设计。
- 视频生成式与潜在状态动力学式路线的直觉，不把世界模型等同于视频生成器。
- 可以服务于候选动作比较、规划、想象中的学习或数据生成；并非所有模型都具备全部用途。
- 与物理仿真器的区别，以及二者可以怎样配合。
- 预测误差累积、分布外失真、策略利用模型漏洞等局限。
- 世界模型是可选能力，不是每个 VLA 系统的必经模块。

**读完产出**：能分清“生成一段看起来合理的视频”和“提供可靠的动作后果预测”。

### 第六章｜模型怎么学：数据、训练目标与能力形成

**核心问题：训练样本是什么，训练究竟在优化什么？**

- 先区分数据：通用图文／视频、机器人示范、仿真交互、真实交互；各自提供什么监督信号。
- 从一条 episode 构造一个样本：时间戳、历史观察、指令、状态、未来动作、mask。
- 遥操作、模仿学习与 Behavior Cloning 的关系：遥操作是采集示范的方式，BC 是模仿学习的一种方法，三者不是平级算法。
- 从预训练模型到机器人适配：数据、动作接口、冻结范围与可训练模块的变化；不假设所有项目按同一顺序进行。
- 不同训练目标的直觉：token 预测、动作回归、去噪／速度场学习、奖励驱动的策略优化。
- Offline 与 online，on-policy 与 off-policy 的最小区分；不在此推导 PPO／SAC／GRPO。
- RL 何时可能有帮助、需要哪些额外条件；不把 VLA 训练默认等同于 RL。
- 泛化与分布偏移：新物体、新场景、新指令和不同机器人本体。

**读完产出**：能解释“给模型一条数据、得到一个 loss、更新哪些参数”，并区分示范学习与交互学习。

### 第七章｜从离线模型到可用机器人：执行、评估和安全

**核心问题：训练成功为什么不等于任务成功？**

- 模型推理、动作队列、控制器执行和新观察之间的时间关系。
- 同步／异步推理与异步 RL 训练的区别。
- 长动作段、延迟和观察新鲜度之间的取舍。
- 分层系统与端到端策略的边界；“大脑／小脑”只作为非严格比喻。
- 离线 loss、动作误差、仿真任务成功率、真机任务成功率分别能证明什么。
- 闭环误差累积、sim-to-real 差距、人类介入及独立安全保护。

**读完产出**：能列出模型接入机器人前需要核验的接口和证据，不把 demo 当作生产可靠性证明。

### 第八章｜回到你的专业：这些模型选择如何改变 Infra？

**核心问题：理解了模型，下一步应该在哪些工程问题上深入？**

- 多模态数据与时序采样 → 数据正确性、解码、预取和存储布局。
- 多模块模型与冻结策略 → 参数／activation 显存、精度、并行与重计算。
- Action chunk 与迭代生成 → 推理时延、执行开销、批处理和实时约束。
- 环境交互与学习 → 资源调度、版本管理、背压、轨迹与恢复。
- 模型、预处理、归一化和控制接口 → 训练到部署的一致性。
- 对照已有 Megatron、长上下文 SFT、verl／AReaL 经验：哪些可迁移，哪些需要重新理解。
- 最小后续实践：查看一个 episode → 理解一个 batch → 跟踪一次 forward/loss → 再做性能分析。

**读完产出**：能提出具体工程问题；不把本章扩成另一份全栈平台架构设计。

## 4. 写法与信息密度

- 首屏提供“一页概念对照＋章节入口”，全文先整体后局部。
- 第一次出现术语，使用“中文直觉＋英文名称＋杯子例子”。
- 每章固定顺序：要解决的问题 → 常见机制 → 例子 → 容易混淆的地方 → 一句话总结。
- 代表模型嵌入相关章节，每条路线选少量例子，不另起冗长排行榜。
- 主线采用自然语言，公式只在确有帮助时补充；数学推导与代码细节后续回链。
- 正文优先控制在约 6,000–8,000 中文字，作为首版编辑目标；先读前两章建立地图，再逐章阅读，不承诺固定阅读时长。
- 后续图示只服务关键关系：执行／学习两种循环、MLLM 与动作策略的分工、动作生成或世界模型机制。大纲阶段不制作图稿。
- 事实、教学示意和趋势判断明确区分；不把学习资料中的方案包装为个人项目经历。
