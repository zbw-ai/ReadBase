# 大模型训练推理 Infra 三天面试冲刺手册设计

## 目标

基于候选人 2026 版简历，生成一份可在首轮面试前 3 天完成复习的 Markdown 手册。目标岗位为社招大模型训练/推理 Infra 高级工程师，薪资目标 100–120 万。内容优先覆盖最简单、最高频、最重要且与简历直接相关的问题。

## 输出位置与形式

- 输出：`private_resume/2026-08-llm-infra-interview-prep.md`
- 形式：中文 Markdown；技术名词保留 English。
- 定位：可直接朗读、复盘和模拟追问的面试作战手册，不写成知识百科。

## 内容优先级

1. 简历项目深挖：AReaL Agentic RL/在线蒸馏、VeRL SFT/RLVR、长上下文与异步 rollout、华为千卡集群交付。
2. 三个核心框架：Megatron-Core、VeRL、AReaL。
3. 训练/推理 Infra 基础：并行策略、显存、MFU、通信、vLLM/SGLang、checkpoint/recovery、性能与故障定位。
4. 高级工程师行为题：项目 ownership、跨团队推动、方案取舍、复盘和薪资档位对应能力。

题目分为：

- `P0`：三天内必须掌握，可支撑首轮面试。
- `P1`：高概率追问，掌握后可显著提升回答深度。
- `P2`：时间允许再看，仅保留少量补充题。

范围与时间预算：

- P0 共 24–30 题，预计复习 6–8 小时；P1 共 20–30 题，预计复习 3–4 小时；P2 不超过 10 题，只用于查漏补缺。
- “P0 Top”是全篇 P0 题目的学习路径与锚点索引，不重复创建另一套问题或答案。
- 每题使用唯一 ID（如 `RESUME-01`、`MEGATRON-03`），并标注优先级、预计复习时长和所属主题，使“三天可完成”可以检查。

## 每道题的固定结构

1. **问题**：面试官可能采用的真实问法。
2. **面试官意图**：区分其在检查概念、真实参与度、系统判断、量化能力还是故障定位能力。
3. **精准回答**：先给结论，再讲机制、工程取舍和结果；P0 简历项目题形成 60–90 秒口述版本，P1/P2 可采用更短答案。
4. **项目证据或知识边界**：有直接项目材料时绑定实际项目、指标和职责边界；若简历只声明“了解”或技能栏列出框架，则明确写“无直接项目证据/仅技能栏声明”，绝不包装成亲自实现。
5. **高概率追问**：给出二至三级追问链和简短答题要点。
6. **危险回答**：标注容易暴露夸大、概念混淆或缺少验证的问题。

上述六项适用于 P0、P1、P2 的每一道题；允许 P1/P2 更简洁，但不得省略“面试官意图”。

## 文档结构

1. 使用方法与三天冲刺安排。
2. 首轮面试最重要的 P0 Top 24–30 学习路径（链接到后续唯一题目，不重复答案）。
3. 简历项目深挖题。
4. Megatron-Core 高频题。
5. VeRL 高频题。
6. AReaL 高频题。
7. 训练推理 Infra 通用题。
8. 高级工程师系统设计与行为题。
9. 三框架对比速查与面试前最后一小时清单。

## 事实与边界

- 简历数据只作为候选人声明，不虚构未提供的硬件型号、集群拓扑、batch size、网络带宽或算法细节。
- 对无法从简历确认的实现细节，明确标成“面试前补齐”，并列出需要准备的数据。
- 框架架构与术语优先依据官方仓库/文档核验，核验截止日为 2026-08-30；来源附录记录官方 URL、访问日期，以及可获得的 release/tag/commit 或文档版本。面试经验只用于判断题目概率，不作为技术事实来源。
- 回答区分“框架机制”“项目事实”“合理推断”，避免把文档知识包装成亲自实现。
- 不复制简历中的手机号、邮箱、年龄、籍贯、民族等与面试题无关的个人信息；保留客户与交付数据的 `x/xx` 脱敏形式，不尝试反推或补全。

## 验收标准

- 首屏即可找到 3 天安排和 P0 题目。
- 每一道 P0/P1/P2 题都有面试官意图；每道 P0 项目题另有可口述答案、项目证据、追问和风险提醒。
- P0/P1/P2 数量和预计复习时长不超过约定预算，P0 Top 只索引、不重复题目。
- Megatron、VeRL、AReaL 的关键机制无明显事实错误，且能相互比较。
- 所有简历数字与源简历一致；未确认信息不被写成事实。
- 框架来源附录包含核验日期与可复核的版本标识；文档不暴露无关个人信息或反推脱敏数据。
- Markdown 标题层级、内部锚点与相对链接有效。
- 文档可在 3 天内按优先级完成，不被低频细节淹没。
